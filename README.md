# Shorts Studio

Студия для подготовки YouTube Shorts и бесплатный браузерный прототип создания видео по идее. HTML, CSS и обычный JavaScript; без сборки, регистрации, платных API, внешних шрифтов и сервера.

## Как открыть

1. Скачайте папку проекта целиком и распакуйте архив.
2. Дважды нажмите на **`index.html`** — сайт откроется в современном браузере (Chrome, Edge, Firefox или Safari).
3. При первом запуске уже открыт демонстрационный проект **«Мы сделаны из звёзд»**.

Подключение к интернету не требуется. Все файлы из папок `js` и `assets`, а также все файлы CSS, должны оставаться рядом с `index.html`.

Для скачивания одним файлом есть [автономный HTML](downloads/Shorts-Studio.html) и [ZIP с этим HTML](downloads/Shorts-Studio.zip). В автономной версии стили, скрипты и иконка встроены в один файл; все функции редактора сохранены.

Для разработки при желании можно запустить статический сервер из папки проекта:

```sh
python3 -m http.server 8080
```

Затем откройте `http://localhost:8080`. Сервер необязателен. Хранилище браузера для адреса сервера и для файла `index.html` раздельное — переносите оба черновика и исходные медиа через ZIP-копию проекта; прежний JSON переносит только текстовую Студию.

## Как пользоваться

Текущая версия показана в интерфейсе. Единственный редактируемый источник номера, дат и заметок об обновлениях — [`js/product.js`](js/product.js). [`CHANGELOG.md`](CHANGELOG.md) формируется из него; порядок подготовки следующего выпуска и локального Git-тега описан в [`RELEASING.md`](RELEASING.md).

### Что нового и сведения о продукте

- Кнопка **«Что нового»** в боковой навигации открывает историю выпусков с датами, основными изменениями и ссылками на реальные PR. При первом посещении новой версии появляется небольшое предложение прочитать изменения. Закрытие предложения или просмотр истории запоминается для текущей версии; повторные посещения его не показывают. Историю всегда можно открыть вручную.
- **«О Shorts Studio»** в том же меню открывает назначение Shorts Studio, список текущих возможностей, номер версии и GitHub-репозиторий.
- Поля правообладателя и контакта изначально пустые. Форма позволяет сохранить достоверные сведения **только в этом браузере**, не меняя публичный сайт. Публичные поля задаются в `rights` внутри `js/product.js`. Изменение этих полей не устанавливает и не подтверждает юридическое право собственности.
- Свободная лицензия проекта автоматически не добавлена. Проверка внешних компонентов и их лицензий приведена в [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

Сведения продукта и отметка просмотра обновления имеют собственные ключи localStorage и не меняют сценарии, видеочерновики, изображения или аудиодорожки. При недоступном хранилище автоматическое предложение отключается, а ручной просмотр остаётся доступен. Очистка данных браузера сбрасывает отметку просмотренной версии и локальные поля.

Состояние текущего проекта появляется в одном toast справа внизу: «Сохранение…», затем «Сохранено на устройстве» после транзакции. Успех скрывается примерно через 2,7 секунды; ошибка остаётся до исправления или смены режима. Toast плавает поверх интерфейса без нижней панели, отступов и изменения размеров рабочей области. При прокрутке он выбирает свободное место, обходя кнопки, включая мобильное скачивание. Верхняя панель больше не закреплена. Предпросмотр на десктопе остаётся рядом с длинным списком сцен, если вся панель помещается по высоте; иначе прокручивается обычным способом. Размер экранного предпросмотра не влияет на разрешение видео. Сведения о готовом файле находятся над скачиванием без внутренней прокрутки. Ручные шаги Safari и автоматические проверки — в [UX_TESTING.md](UX_TESTING.md).

### Работа в редакторе

- **Сценарий:** напишите или вставьте текст. Счётчик слов и примерное время озвучки обновляются сразу. Расчёт: **150 слов в минуту**, то есть 0,4 секунды на слово.
- **Разбить на сцены:** каждое предложение или отдельная строка становится сценой. Повторная разбивка заменяет текущие сцены после подтверждения.
- **Сцены:** меняйте текст, добавляйте и удаляйте сцены. Нажмите на номер сцены, чтобы выбрать её. Длительность рассчитывается автоматически.
- **Предпросмотр:** вертикальный экран 9:16 показывает выбранную сцену. Стрелки переключают сцены, кнопка воспроизведения проигрывает их по рассчитанному времени. Это текстовый предпросмотр без озвучки и генерации видео.
- **Оформление:** три стиля субтитров, три размера текста и три варианта фона. Выбор сохраняется в проекте.
- **Субтитры:** автоматически создаются из сцен. **Экспорт SRT** скачивает UTF-8-файл с последовательными таймкодами и миллисекундами. Пустые сцены пропускаются; каждая сцена — один блок субтитров. Время соответствует оценке чтения, а не выравниванию с аудио. SRT не хранит оформление — задайте его в видеоредакторе.
- **Сохранение:** изменения автоматически сохраняются в IndexedDB через 300 мс, при непрерывном вводе — с запуском записи не реже двух секунд. Перед закрытием дождитесь «Сохранено». После перезагрузки восстановятся название, сценарий, сцены, выбранная сцена и оформление. Правки сцен не изменяют исходный сценарий; предпросмотр и SRT используют именно сцены.
- **Скачать JSON редактора / Открыть JSON:** прежний `.shorts.json` переносит текстовый проект Студии без медиа видеорежима. На узких экранах эти действия доступны в компактной панели файлов под названием проекта.
- **Новый проект:** создаёт пустой проект после подтверждения замены текущего. Перед заменой скачайте старый проект, если он ещё понадобится. Хранится один активный проект.

Локальная база принадлежит origin сайта и профилю браузера. В приватном режиме, при запрете локального хранения, перемещении файлов или очистке данных сохранение может быть недоступно или исчезнуть. Приложение показывает ошибку сохранения; используйте скачивание проекта для надёжной резервной копии. Для стабильного хранения в разных браузерах удобнее постоянный адрес статического сервера. Конфликт вкладок останавливает перезапись устаревшей копией и показывает предупреждение.

Полный порядок миграции, гарантии транзакций, ограничения Safari и новые тесты описаны в [PROJECT_STORAGE.md](PROJECT_STORAGE.md). Старые localStorage и база изображений не удаляются и не обновляются. Аудио, уже утраченное старой версией после закрытия вкладки, потребуется выбрать заново. `.shorts.json` остаётся копией только текстового редактора; для обоих режимов и оригинальных медиа используйте ZIP ниже.

## ZIP-копия и восстановление проекта

Подготовлено для **1.4.0, ещё не опубликовано**. В группе «Проект» нажмите **«Скачать ZIP-копию»** (на телефоне — **«ZIP-копия»**). ZIP хранит **оба независимых черновика**, сценарии, сцены и настройки, оригинальные PNG/JPG/WebP, голос и музыку. После подготовки нажмите ссылку скачивания и храните файл вне браузера. Позднейшие правки не меняют уже подготовленный снимок; можно продолжить редактирование в фоне и затем создать новую копию.

**«Восстановить ZIP»** проверяет архив и предлагает заменить оба текущих черновика, включая несохранённые правки. Сначала сохраните нужную текущую работу. Только после явного подтверждения данные записываются одной транзакцией; при квоте, сбое или конфликте вкладок частичной замены не происходит. После успеха страница перезагружается. ZIP переносим между браузерами/устройствами и автономным HTML, не зависит от исходной IndexedDB. Если старый оригинал утрачен, экспорт честно сообщает об этом и не выдаёт неполную копию.

Предел первой версии — **64 МиБ на архив**, без сжатия и перекодирования. ZIP не зашифрован. Большим проектам может не хватить памяти/квоты Safari; старые данные ради освобождения места не удаляются. Исходный ZIP Shorts Studio не следует перепаковывать: поддерживается строгий ZIP32 STORE. Готовое MP4/WebM и прежний текстовый JSON скачиваются отдельно. ZIP самого приложения в `downloads` также не является копией пользовательского проекта.

Формат, ограничения, гарантии, тесты и пошаговая проверка Safari: [PROJECT_BACKUP.md](PROJECT_BACKUP.md).

## Создать видео по идее

Новый режим доступен через **«Создать видео по идее»** над редактором или **«Видео по идее»** в меню. Исходный редактор и его проект сохраняются отдельно. Начальные сцены режима видео — готовый демонстрационный ролик **«Дом, который помнит»**, длительность **18 секунд**.

1. Нажмите **«Демо · 18 сек»**, чтобы вернуться к примеру, или введите свою идею и нажмите **«Создать сценарий»**. Генератор использует локальные сценарные шаблоны и ключевые слова, без нейросетей и сетевых запросов. Это короткая заготовка, которую можно редактировать, а не гарантированно уникальная история.
2. Выберите длительность, атмосферу и оформление субтитров. Сцены можно менять, удалять и добавлять (до 12 сцен, до 280 символов в сцене). В автоматическом режиме время распределяется по словам. Для собственного монтажа выберите **«Вручную по сценам»** или измените поле **«Длительность, сек»** любой сцены: остальные длительности сначала копируются из текущей автоматической разбивки. Ручная длительность каждой сцены — от **0,5 до 60 секунд**, общий хронометраж — не больше **60 секунд**. Неверные значения блокируют запись с объяснением; действительный итог показан в настройках. В ручном режиме можно оставить текст пустым, чтобы показать изображение без субтитров.
3. Для каждой сцены выберите **«Моё изображение»** и загрузите PNG, JPG или WebP, либо оставьте прежний **«Анимированный фон»**. Изображение заполняет 9:16 с обрезкой краёв; доступны приближение, отдаление, панорама влево/вправо и неподвижная камера. Переход к сцене — растворение, сдвиг, мягкий зум или прямая склейка. Переходы накладывают изображения друг на друга, без промежуточного чёрного экрана. Настройка перехода первой сцены не используется.
4. Загрузите **голос** и **фоновую музыку** в две независимые секции. Для каждого файла действует предел **25 МБ / 10 минут**, декодирование зависит от браузера (обычно WAV, MP3, M4A, OGG). У каждой дорожки свой ползунок громкости; изменение одной не меняет другую. Музыке можно задать появление и затухание от **0 до 10 секунд**. Ноль отключает соответствующий fade; при пересечении длинных fades на короткой дорожке музыка остаётся тише. Более длинное аудио обрезается, короткое заканчивается тишиной. Музыка не зацикливается; она затухает к своему окончанию или к концу ролика — что наступит раньше.
5. Нажмите **«Смотреть»**. Предпросмотр и запись используют один Canvas-рендерер и один Web Audio-микшер: изображения, движение камеры, переходы, обе дорожки и fades попадают в готовый файл. Ползунок позволяет перейти к нужному моменту; при перемотке громкость музыки соответствует этому месту исходной огибающей.
6. Нажмите **«Собрать видео»**. Запись идёт в реальном времени: 18-секундный пример займёт примерно 18 секунд плюс завершение файла. Держите вкладку видимой; при её скрытии запись прерывается с понятным сообщением. Можно отменить запись кнопкой; частичный файл не выдаётся за готовый.
7. Посмотрите готовое видео и нажмите **«Скачать видео»**. Формат выбирается по `MediaRecorder.isTypeSupported()` и фактическому запуску кодека: предпочтение **MP4**, затем **WebM**. Можно явно выбрать WebM. Расширение всегда соответствует MIME записанного контейнера — WebM не переименовывается в MP4.

Видео имеет размер **720 × 1280 (9:16)**; Canvas запрашивает **24 кадра/с**, фактическая частота зависит от производительности устройства. Четыре рисуемых фона включают движущиеся облака, дождь, свет в окнах, звёзды, планеты, горы и неоновые орбиты. Переходы между сценами и субтитры встраиваются непосредственно в изображение. Это процедурная графика, не генерация фотореалистичных кадров. Автоматической озвучки нет — для звука загрузите свой файл. Микрофон, камера и API-ключи не нужны.

**«Субтитры SRT»** в новом режиме экспортирует таймкоды именно видеоролика, включая короткие группы слов на экране. **«Открыть сценарий в редакторе»** переносит текст только после подтверждения замены активного проекта; в редакторе снова действует оценка 150 слов/мин.

Каждая группа субтитров ограничена точными границами своей сцены, и следующий текст начинается в момент начала следующей сцены. Граница визуального перехода не добавляет время и не меняет таймкоды. Голос автоматически не распознаётся: для совпадения с готовой озвучкой задайте длительности сцен вручную. В экспортированном файле голос и музыка сведены в **один смешанный аудиопоток**, а не два переключаемых потока. В проекте их громкость независима; мягкий лимитер снижает риск перегруза при сложении.

Видеопроект и текстовый проект сохраняются независимо в IndexedDB `shorts-studio.projects`. Исходные изображения, голос и музыка сохраняются вместе с настройками и восстанавливаются после перезагрузки и повторного открытия браузера при доступном хранилище. Готовое видео нужно собрать повторно. Скачивайте результат до закрытия страницы. При изменении текста или настроек устаревший результат сбрасывается.

Изображения хранятся локально как исходные бинарные данные в **IndexedDB** (`shorts-studio.projects/assets`), вместе с исходными аудиофайлами. Снимок и новые материалы записываются одной транзакцией. Поддерживаются только PNG/JPG/WebP до **15 МБ / 40 мегапикселей**; SVG и внешние ссылки не используются, поэтому Canvas не загрязняется чужим origin. Изображения с прозрачностью накладываются на анимированную подложку. При доступном хранилище изображения, камера, переходы и длительности восстанавливаются после перезагрузки. Они не входят в JSON-проект обычного редактора — сохраняйте оригиналы файлов. Декодирование зависит от браузера; если WebP не читается, используйте PNG или JPG. Статический декодер использует один кадр анимированных PNG/WebP.

В приватном режиме, при недостатке квоты, запрете IndexedDB или открытии через `file://` браузер может запретить постоянное хранение изображений. В этом случае текущий предпросмотр и экспорт продолжают работать, а интерфейс помечает изображения как доступные только во вкладке. После перезагрузки отсутствующий файл нужно выбрать заново или явно переключить сцену на анимированный фон: запись с потерянным изображением блокируется, вместо молчаливой замены или чёрного кадра. На постоянном адресе локального сервера или GitHub Pages хранение обычно предсказуемее; это не обязательный сервер генерации. Очистка данных браузера удаляет и изображения.

Поддержка Canvas Capture, MediaRecorder, кодеков MP4/WebM и Web Audio проверяется во время работы. Если запись недоступна, генерация текста и просмотр анимации продолжают работать. Для неподдерживаемого или повреждённого аудио показывается ошибка. В потоковом WebM по возможности дописывается длительность в заголовок без перекодирования; уже индексированные файлы не сдвигаются. Поддержка и быстродействие на смартфонах зависят от браузера, доступной памяти и режима энергосбережения.

## Как проверить видеогенератор вручную

- Откройте `index.html` (или локальный сервер, как описано выше), перейдите в новый режим и выберите демо на 18 секунд.
- Запустите предпросмотр: дождь, свет, камера и субтитры должны двигаться; за время ролика сменятся 6 сцен.
- Загрузите короткий WAV/MP3 и соберите видео. Проверьте рост прогресса, скачивание, вертикальное изображение, меняющиеся сцены, субтитры и звук. После окончания короткой дорожки должна быть тишина.
- Выберите **WebM** и повторите запись: должен скачаться `.webm`, а не `.mp4`. Выбор «Авто» использует MP4 только при реальной поддержке браузером.
- Начните запись и нажмите **«Отменить запись»**. Неполный файл не должен появиться. При смене вкладки запись также прерывается с сообщением; обычный предпросмотр ставится на паузу.
- Измените сценарий и перезагрузите страницу: черновик видео должен восстановиться, а старый проект редактора — остаться прежним.
- В двух сценах загрузите разные изображения, задайте **2** и **3** секунды. Проверьте движение камеры и переход, затем экспортируйте ролик: общая длительность должна быть около 5 секунд (допуск на завершение MediaRecorder — несколько кадров). В SRT первая сцена заканчивается на `00:00:02,000`, вторая — на `00:00:05,000`.
- Загрузите голос и музыку одновременно, установите разную громкость, появление/затухание музыки по 1 секунде. Проверьте скачанный файл: слышны обе дорожки, голос не затухает вместе с музыкой. По очереди обнулите громкость голоса и музыки и повторите экспорт.

## Будущие ElevenLabs и генерация видео

Редактор и генератор видео не делают сетевых запросов. `ShortsIntegrations` предоставляет `register(name, provider)`, `isAvailable(name)` и асинхронный `run(name, payload, { signal })`. Они не зависят от наличия провайдеров.

Контракты для будущих адаптеров:

```js
// Запрос озвучки через собственный backend:
ShortsIntegrations.register('voice', {
  async run({ scenes, voiceId }, { signal } = {}) {
    // POST /api/voice; ключ ElevenLabs хранится только на backend.
    // Возврат: { audio: Blob, sceneDurationsMs: number[] }
  }
});

// Генерация видео через собственный backend:
// video.run({ scenes, style, audio }, { signal }) -> { video: Blob }
```

Это контракт расширения для внешних сервисов, а не реализованная озвучка: для подключения ElevenLabs понадобится отдельный backend, который хранит API-ключ, обращается к сервису и возвращает аудио и реальные длительности сцен. При необходимости серверного рендера можно добавить адаптер FFmpeg. Новый бесплатный режим уже записывает видео локально через Canvas/MediaRecorder и использует собственный точный таймлайн. Для будущего выравнивания с автоматически сгенерированной озвучкой потребуется учитывать реальные аудиодлительности. Поле `version` в JSON позволяет мигрировать формат проекта. `AbortSignal` предусмотрен для отмены длительных задач. Не помещайте ключи в HTML, JavaScript, JSON-проекты или `localStorage`.

## Проверки

Для вычислений нужен только Node.js 18+:

```sh
node --test tests/*.test.cjs
```

Согласованность версии и документации:

```sh
node scripts/release.cjs check
python3 tests/product-browser.py
```

Тест окон продукта проверяет текущую версию и историю, одноразовое уведомление, сохранение и сброс локальных полей, безопасное отображение текста, клавиатурную навигацию, 4 ширины экрана и неизменность существующих проектов. Для автономного HTML можно добавить `PRODUCT_ENTRY=downloads/Shorts-Studio.html`.

WebKit и мобильная эмуляция iPhone:

```sh
python3 -m playwright install --with-deps webkit
PRODUCT_BROWSER=webkit python3 tests/product-browser.py
```

Настоящий Safari проверяется отдельным заданием **Native Safari on macOS** в Actions. Оно использует системный `/usr/bin/safaridriver`, подтверждает настоящий Safari в capabilities, проверяет окна продукта, уведомление, локальные поля, адаптивность и пробует записать и прочитать короткое видео при поддержке API. На macOS проверку можно повторить так:

```sh
sudo /usr/bin/safaridriver --enable
python3 tests/safari-product.py
```

На Linux этот тест намеренно не подменяет Safari другим браузером. WebKit с профилем iPhone — эмуляция, не физический iPhone. Если запись в конкретном Safari недоступна, тест отдельно сообщает это ограничение и проверяет понятное сообщение интерфейса; успешная проверка окон не выдаётся за успешный экспорт. Ограничение локальной среды на скачивание WebKit не относится к приложению: тестовый браузер устанавливается в изолированном задании CI.

Safari может сообщать поддержку MediaRecorder, но фактически вернуть пустой файл; в таком случае текущий генератор выводит ошибку и предлагает другой формат. Если Safari возвращает пустой MP4, выберите **«WebM»** в поле формата записи и повторите сборку, если браузер поддерживает этот кодек. При зависшем завершении кодека дождитесь сохранения и перезагрузите страницу перед повторной записью; CI после отказа MP4 также восстанавливает сохранённые медиа в новом документе и требует полноценный WebM. В CI тест восстановления проекта проверяет этот существующий путь через интерфейс и требует реальный видеофайл. Отдельный диагностический тест короткой записи без звука при ошибке сравнивает её с **точным базовым коммитом PR** в том же Safari. В этом отдельном диагностическом тесте предупреждение о существующем ограничении допустимо только при одинаковой ошибке на обеих версиях и побайтово неизменённых модулях расчёта, рендера, микшера и записи, а также исходных стилях. Если базовая версия записывает видео, а PR нет, проверка падает. Такое предупреждение видно в Actions и его итоговом отчёте; оно не означает успешную запись в Safari. При локальном запуске без `SAFARI_BASELINE_ROOT` ошибка экспорта всегда завершает тест неудачей. Запись с изображениями и двумя звуковыми дорожками отдельно проверяется настоящими файлами в Chromium и FFmpeg.

Для проверки интерфейса нужен Python с пакетом `playwright` и Chromium. Укажите путь к системному браузеру, если он отличается:

```sh
CHROMIUM_PATH=/usr/bin/chromium python3 tests/browser.py
```

Для тестов видеогенератора дополнительно нужны `ffmpeg` и `ffprobe` (пакет FFmpeg). Запуск:

```sh
CHROMIUM_PATH=/usr/bin/chromium python3 tests/video-browser.py
```

Тест записывает **настоящее 18-секундное видео** с синтетической аудиодорожкой, скачивает его и проверяет декодирование, размер 720×1280, длительность, смену кадров, наличие звука и тишину после конца короткой дорожки. Затем он записывает настоящий WebM при недоступном MP4 и проверяет контейнер и расширение. Также проверяются предпросмотр, сохранение черновика, отмена записи, скрытие вкладки, отсутствующие API, отказ кодека, ошибки аудио и подтверждение переноса в редактор. Обычно требуется 30–60 секунд. Медиаданные создаются во временной папке и удаляются после теста; ваши проекты и файлы не используются.

Проверка новых медиафункций:

```sh
CHROMIUM_PATH=/usr/bin/chromium python3 tests/media-browser.py
```

Тест загружает PNG/JPG/WebP через настоящий интерфейс, восстанавливает изображения из IndexedDB и записывает реальные MP4/WebM с двумя различимыми синтетическими аудиосигналами. FFmpeg/ffprobe проверяют контейнер, декодирование и длительность; анализ пикселей подтверждает правильное изображение каждой сцены и отсутствие чёрных кадров во всём файле. Спектральный анализ подтверждает наличие обеих дорожек, независимость громкости, плавное появление/затухание музыки и неизменность голоса. Дополнительно проверяются таймкоды 2/3-секундных сцен, все переходы, ограничения общей длительности и недоступное хранилище. Это локальные тестовые сигналы и изображения, пользовательские файлы не используются.

Чтобы повторить те же проверки для автономного HTML после упаковки:

```sh
python3 scripts/prepare-site.py
SHORTS_MEDIA_ENTRY=downloads/Shorts-Studio.html CHROMIUM_PATH=/usr/bin/chromium python3 tests/media-browser.py
```

Браузерный тест сначала открывает непосредственно `index.html`. Если системная политика Chromium блокирует `file://`, тест сообщает об этом и временно запускает статический HTTP-сервер только на `127.0.0.1` для проверки тех же файлов. Именно этот запасной вариант использован при проверке в облачной среде. Прямой запуск из файла в этой среде проверить нельзя из-за политики браузера. Тест использует временную папку для загрузок и изолированное хранилище, не затрагивая ваши проекты.

Пакеты для тестирования перечислены в `requirements-dev.txt`; они не нужны пользователям сайта. В CI используется Chrome/Chromium, уже установленный в образе Ubuntu 24.04; при его отсутствии выполняется `python -m playwright install --with-deps chromium`. Задания Chromium и WebKit ограничены 20 минутами, настоящий Safari — 15 минутами; проверки ZIP обязательны вместе с прежними проверками.

## Проверки и отдельная публикация GitHub Pages

Merge, push в `main`, PR и повторный запуск проверок **не публикуют сайт**. Workflow **Check Shorts Studio** (`pages.yml`) автоматически запускает все прежние тесты Chromium, WebKit/мобильной эмуляции и настоящего Safari, готовит и проверяет `_site`. Его ручной запуск также выполняет только проверки. В нём нет deploy-job и разрешений `pages: write`/`id-token: write`.

Публикация — отдельное решение владельца после ревью:

1. Объедините проверенные изменения в `main`, когда решите это сделать. Сайт останется прежним. Статус продукта, дата, Git-теги и GitHub Release от merge не изменяются.
2. Следуйте [RELEASING.md](RELEASING.md): отдельно проверьте метаданные выпуска и выберите **точный коммит** для публикации. Сейчас 1.4.0 остаётся `unreleased`; workflow не редактирует историю автоматически.
3. Перед первым запуском публикации в **Settings → Pages** сохраните Source **GitHub Actions**, а в **Settings → Environments → github-pages** включите **Required reviewers → свой аккаунт**, отключите admin bypass и оставьте **Prevent self-review** выключенным. Эти правила нужны в том числе для старых runs. Вариант **Deploy from a branch** обходит ручные правила и для этого процесса не используется.
4. В **Actions → Publish GitHub Pages → Run workflow** выберите `main`, вставьте полный 40-символьный SHA выбранного коммита в `commit_sha` и введите `PUBLISH` в `confirmation`. Запускать публикацию может только владелец репозитория. При несовпадении SHA, другой ветке/пользователе или отсутствии подтверждения запрос отклоняется.
5. Новый запуск заново проверит этот коммит всеми тремя браузерными заданиями, подготовит и загрузит Pages artifact. При ошибке любой обязательной проверки деплоя не будет. Артефакты обычных проверок не публикуются.
6. После успешных проверок владелец отдельно одобряет deployment окружения **github-pages** в **Review deployments**. Окружение уже ограничено `main`; обязательное одобрение и запрет **Allow administrators to bypass configured protection rules** нужно заранее включить в шаге 3. После одобрения выполняется прежний `actions/deploy-pages`.

Повторный запуск даже ранее одобренного release-run не публикует снова: нужен **новый** явный запуск с SHA и `PUBLISH`, затем одобрение окружения. Старые исторические runs используют прежний YAML; после ручного включения обязательного одобрения окружения оно защищает и их. Интеграция Codex получила 403 при попытке изменить это правило, поэтому не считайте его уже настроенным. Не одобряйте deployment из старого автоматического workflow — для нового выпуска используйте Publish GitHub Pages.

Адрес сайта остаётся `https://nw95z6kbbd-wq.github.io/shorts-lab/`. Загружается `_site` с приложением и автономными HTML/ZIP, без Git-метаданных и тестовых инструментов; относительные пути сохраняют работу в `/shorts-lab/`. Публикация не создаёт Release, не отправляет теги и не повышает версию.

Локально повторить подготовку и проверить именно публикуемые файлы можно так:

```sh
python3 scripts/prepare-site.py
python3 tests/pages.py
```

Подготовка требует только стандартную библиотеку Python; проверка — Playwright и Chromium. Скрипт не меняет исходный интерфейс и логику: он копирует ресурсы в `_site` и обновляет производные файлы в `downloads`. После изменения исходников повторите подготовку и включите обновлённые файлы `downloads` в коммит. Пользовательские проекты в браузере не затрагиваются; локальное хранение на GitHub Pages будет отдельным от хранения у локального файла и локального сервера.


Навигация разделена на «Студия» (сценарий, сцены, субтитры) и «Создание с ИИ». Действующий пункт «Видео по идее» обозначен как шаблонный: нейросеть не подключена. Счётчик под идеей берёт прежний лимит из `ShortsVideoCore.IDEA_LIMIT`. Как и раньше, проверка использует длину UTF-16: эмодзи и составные знаки могут занимать несколько позиций. Текст сверх лимита виден целиком, не обрезается и не заменяет последнюю корректную идею в IndexedDB; предупреждение остаётся до исправления. Сценарии, изображения и звук при этом не удаляются.

История поддерживает уровни `highlight`, `standard`, `patch` из `js/product.js`. Это редакционная значимость, независимая от SemVer. Неопубликованная запись имеет `status: "unreleased"` и не получает выдуманную дату или merge-коммит. Ручная проверка патча описана в [PATCH_UX_TESTING.md](PATCH_UX_TESTING.md).

Техническая подготовка ручной Студии (DTO 2, физическая версия IndexedDB 2, защита медиа и старых вкладок, ограничения отката и ZIP): [STUDIO_DATA_MODEL.md](STUDIO_DATA_MODEL.md). Нового UI ручной видеосборки на этом этапе нет; версия продукта и статус выпуска не изменены.
