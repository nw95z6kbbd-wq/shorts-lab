# Shorts Studio

Готовая первая версия студии для подготовки YouTube Shorts. HTML, CSS и обычный JavaScript; без сборки, регистрации, платных API, внешних шрифтов и сервера.

## Как открыть

1. Скачайте папку проекта целиком и распакуйте архив.
2. Дважды нажмите на **`index.html`** — сайт откроется в современном браузере (Chrome, Edge, Firefox или Safari).
3. При первом запуске уже открыт демонстрационный проект **«Мы сделаны из звёзд»**.

Подключение к интернету не требуется. Все файлы из папок `js` и `assets`, а также `styles.css`, должны оставаться рядом с `index.html`.

Для скачивания одним файлом есть [автономный HTML](downloads/Shorts-Studio.html) и [ZIP с этим HTML](downloads/Shorts-Studio.zip). В автономной версии стили, скрипты и иконка встроены в один файл; все функции редактора сохранены.

Для разработки при желании можно запустить статический сервер из папки проекта:

```sh
python3 -m http.server 8080
```

Затем откройте `http://localhost:8080`. Сервер необязателен. Хранилище браузера для адреса сервера и для файла `index.html` раздельное — переносите проекты через JSON.

## Как пользоваться

- **Сценарий:** напишите или вставьте текст. Счётчик слов и примерное время озвучки обновляются сразу. Расчёт: **150 слов в минуту**, то есть 0,4 секунды на слово.
- **Разбить на сцены:** каждое предложение или отдельная строка становится сценой. Повторная разбивка заменяет текущие сцены после подтверждения.
- **Сцены:** меняйте текст, добавляйте и удаляйте сцены. Нажмите на номер сцены, чтобы выбрать её. Длительность рассчитывается автоматически.
- **Предпросмотр:** вертикальный экран 9:16 показывает выбранную сцену. Стрелки переключают сцены, кнопка воспроизведения проигрывает их по рассчитанному времени. Это текстовый предпросмотр без озвучки и генерации видео.
- **Оформление:** три стиля субтитров, три размера текста и три варианта фона. Выбор сохраняется в проекте.
- **Субтитры:** автоматически создаются из сцен. **Экспорт SRT** скачивает UTF-8-файл с последовательными таймкодами и миллисекундами. Пустые сцены пропускаются; каждая сцена — один блок субтитров. Время соответствует оценке чтения, а не выравниванию с аудио. SRT не хранит оформление — задайте его в видеоредакторе.
- **Сохранение:** изменения автоматически сохраняются в `localStorage` через 300 мс и при уходе со страницы. После перезагрузки восстановятся название, сценарий, сцены, выбранная сцена и оформление. Правки сцен не изменяют исходный сценарий; предпросмотр и SRT используют именно сцены.
- **Скачать проект / Открыть проект:** резервная копия `.shorts.json` позволяет перенести работу на другое устройство. На узких экранах эти действия доступны в компактной панели файлов под названием проекта.
- **Новый проект:** создаёт пустой проект после подтверждения замены текущего. Перед заменой скачайте старый проект, если он ещё понадобится. Хранится один активный проект.

`localStorage` принадлежит браузеру и адресу страницы. В приватном режиме, при запрете локального хранения, перемещении файлов или очистке данных сохранение может быть недоступно или исчезнуть. Приложение показывает ошибку сохранения; используйте скачивание проекта для надёжной резервной копии. Для стабильного хранения в разных браузерах удобнее постоянный адрес статического сервера. Одновременное редактирование в нескольких вкладках не поддерживается.

## Структура

```text
index.html           Интерфейс, доступные подписи и диалоги
styles.css           Адаптивный тёмный дизайн и анимации
assets/favicon.svg   Локальная иконка
js/core.js           Слова, сцены, длительности, таймкоды, SRT, формат проекта
js/storage.js        localStorage и обработка ошибок
js/app.js            Редактор, предпросмотр, воспроизведение, загрузка файлов
js/integrations.js   Реестр будущих провайдеров озвучки и генерации видео
tests/core.test.cjs   Тесты вычислений и формата проекта
tests/browser.py     Проверки реального браузера, включая открытие через file://
tests/pages.py       Проверки готового сайта по пути /shorts-lab/
scripts/prepare-site.py  Подготовка статического сайта и автономных файлов
downloads/           Готовые автономные HTML и ZIP
.github/workflows/pages.yml  Проверки PR и публикация main на GitHub Pages
```

Используются обычные скрипты с `defer`, а не ES-модули: это позволяет открыть приложение напрямую через `file://` без ограничений загрузки модулей. Пользовательский текст добавляется через `textContent` и `value`, без интерпретации HTML. В скачиваемом SRT угловые скобки заменяются типографскими, чтобы текст не превратился в команды форматирования.

## Будущие ElevenLabs и генерация видео

Первая версия не делает сетевых запросов. `ShortsIntegrations` предоставляет `register(name, provider)`, `isAvailable(name)` и асинхронный `run(name, payload, { signal })`. Редактор и экспорт не зависят от наличия провайдеров.

Контракты для будущих адаптеров:

```js
// Запрос озвучки через собственный backend:
ShortsIntegrations.register('voice', {
  async run({ scenes, voiceId }, { signal } = {}) {
    // POST /api/voice; ключ ElevenLabs хранится только на backend.
    // Возврат: { audio: Blob, sceneDurationsMs: number[] }
  }
});

// Генерация видео через собственный backend:
// video.run({ scenes, style, audio }, { signal }) -> { video: Blob }
```

Это контракт расширения, а не реализованная озвучка: для подключения ElevenLabs понадобится отдельный backend, который хранит API-ключ, обращается к сервису и возвращает аудио и реальные длительности сцен. Для генерации видео аналогично можно добавить серверный адаптер рендера (например, FFmpeg). Перед экспортом синхронизированных субтитров потребуется переключить расчёт таймлайна с оценки по словам на реальные аудиодлительности. Поле `version` в JSON позволяет мигрировать формат проекта. `AbortSignal` в контракте предусмотрен для отмены длительных задач. Не помещайте ключи в HTML, JavaScript, JSON-проекты или `localStorage`.

## Проверки

Для вычислений нужен только Node.js 18+:

```sh
node --test tests/core.test.cjs
```

Для проверки интерфейса нужен Python с пакетом `playwright` и Chromium. Укажите путь к системному браузеру, если он отличается:

```sh
CHROMIUM_PATH=/usr/bin/chromium python3 tests/browser.py
```

Браузерный тест сначала открывает непосредственно `index.html`. Если системная политика Chromium блокирует `file://`, тест сообщает об этом и временно запускает статический HTTP-сервер только на `127.0.0.1` для проверки тех же файлов. Именно этот запасной вариант использован при проверке в облачной среде. Прямой запуск из файла в этой среде проверить нельзя из-за политики браузера. Тест использует временную папку для загрузок и изолированное хранилище, не затрагивая ваши проекты.

Пакеты для тестирования перечислены в `requirements-dev.txt`; они не нужны пользователям сайта. В CI Chromium устанавливается командой `python -m playwright install --with-deps chromium`.

## Публикация через GitHub Pages

1. Объедините Pull Request с готовыми файлами в `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. Для изменения этой настройки нужны права администратора; GitHub Actions должны быть разрешены. Для приватного репозитория нужна подписка GitHub с поддержкой Pages.
3. В **Actions** запустите **Check and deploy GitHub Pages → Run workflow**, выбрав `main`, если автоматический запуск после объединения уже завершился до включения Pages. Следующие обновления `main` публикуются автоматически после успешных проверок.
4. Готовый адрес будет указан в настройках Pages и в результате задания **Deploy to GitHub Pages**. Для стандартных настроек этого репозитория ожидаемый адрес — `https://nw95z6kbbd-wq.github.io/shorts-lab/`. Само наличие этих инструкций не означает, что сайт уже опубликован.

На Pull Request выполняются проверки; публикация запускается только для `main`. Загружается папка `_site` с файлами приложения и скачиваемыми HTML/ZIP — без Git-метаданных и тестовых инструментов. Пути к ресурсам относительные, поэтому сайт работает в подпапке `/shorts-lab/`. `.nojekyll` также позволяет использовать вариант Pages **Deploy from a branch → main → /(root)** вместо workflow; выберите один способ публикации.

Локально повторить подготовку и проверить именно публикуемые файлы можно так:

```sh
python3 scripts/prepare-site.py
python3 tests/pages.py
```

Подготовка требует только стандартную библиотеку Python; проверка — Playwright и Chromium. Скрипт не меняет исходный интерфейс и логику: он копирует ресурсы в `_site` и обновляет производные файлы в `downloads`. После изменения исходников повторите подготовку и включите обновлённые файлы `downloads` в коммит. Пользовательские проекты в браузере не затрагиваются; локальное хранение на GitHub Pages будет отдельным от хранения у локального файла и локального сервера.
