# Канонический Editor Canvas v1

Внутренняя подготовка 1.4.0 Unreleased. UI, исходные DTO, IndexedDB v2,
ZIP v1/v2, версия и выпуск не меняются. Исходная точка — main
`801d2f6` после PR #15; [push CI 40641664360](https://github.com/nw95z6kbbd-wq/shorts-lab/actions/runs/40641664360)
успешен. До изменений прошли 102 Node-теста и 60 точных Video-кадров.

## Граница профилей

`editor-profile.js` — чистые константы, строгие настройки, перенос/fit и агрегаты
прогресса. `editor-canvas.js` — рисование Editor, заимствованных изображений и
переходов. Единственное дополнение старого `video-renderer.js` — точный dispatch
для `plan.source.mode === 'editor'`. Его Video-тело не меняется. Recorder, микшер,
media/render sessions, Video adapter и публичные makePlan/frameAt сохранены.
`frameAt()` использует бинарный поиск первого endMs > time с тем же clamp/fallback.
Полные Video-планы/SRT/границы и 200 наборов проверяются прежними эталонами.

Editor adapter читает отредактированные сцены, не исходный script, не создаёт ID
и не меняет DTO. Временная нормализация DTO 1 не сохраняет DTO 2. Известные поля
оформления старого DTO могут отсутствовать (его прежние значения по умолчанию),
но неизвестные названия/значимые поля нельзя тихо нормализовать.
`appearance.requested = {namespace:'editor', theme, caption, size}`;
`resolved = {renderer:'editor-canvas-v1', layout:'editor-v1', theme, caption, size}`.
Поддержка проверяется перед рисованием; неизвестные поля/смешанные профили и
несогласованные resolved значения отвергаются. Текст всё ещё может не поместиться.

## Перенос и отказ вместо обрезания

Пробельные последовательности схлопываются; явные LF/CRLF дают перенос строки.
Длинное слово делится по extended grapheme clusters Intl.Segmenter (включая
combining marks, emoji modifiers и ZWJ семьи). Без Intl.Segmenter — RESOURCES,
без опасного fallback по UTF-16. Кириллица, латиница и смешанные Unicode-тексты
не обрезаются. Направление компоновки — LTR, формирование glyph внутри слова
делает native Canvas; полноценный редактор RTL-абзацев сюда не входит.

Размер уменьшается шагом 2,5 px от выбранного nominal до минимума:
small 40, medium 45, large 52,5. Межстрочный интервал остаётся 1,3.
Проверяются ширина каждой grapheme, вся высота вместе с padding и реальные
actualBoundingBox границы каждого рисуемого run; высокие combining marks не
могут незаметно выйти за область. Без этих метрик Canvas выдаёт RESOURCES.
Если ни один размер не подошёл — TEXT_OVERFLOW **до изменения пикселей кадра**.
Не добавляются ellipsis, скрытые хвосты, scroll, страницы или автоматические chunks.
Пользователь должен сократить сцену либо явно выбрать другой поддерживаемый режим.

Editor-scene показывает текст одной сцены, Video — прежние короткие группы.
Уже явный DTO 2 chunks сохраняется; отключённые субтитры не рисуются.
Пустой текст не подменяется UI-подсказкой. При положительной ручной длительности
текст только из emoji/символов теперь также получает scene cue: подсчёт слов
по-прежнему оценивает reading duration, но не должен скрывать видимый Unicode.
В reading-режиме нулевая оценка остаётся нулевой; исходники не переписываются.

Arial/Unicode fallback и растеризация принадлежат ОС/браузеру. Алгоритм
детерминирован при одинаковых метриках; перенос и fit на другой платформе могут
отличаться. Нельзя обещать побитовый CSS/Canvas или межплатформенный текст.
Семейство/геометрия/границы задаются явно, внешний шрифт и CDN не требуются.

## Осознанные отличия от DOM/CSS

Старый UI остаётся прежним. Его responsive размеры и CSS-прокрутка — эскиз,
Canvas же имеет фиксированную область и ошибку переполнения. Нет фиктивных
текстов для пустых сцен. CSS backdrop-filter, inset shadow, отрицательный
letter-spacing, blur/растеризация и responsive font overrides не копируются
побитово: выше задан самостоятельный профиль с теми же узнаваемыми особенностями.
SVG/Canvas текст также может немного различаться по сглаживанию.

## Большие планы и ресурсы

Бинарный поиск сцены/cue: O(log N)/O(log M); никаких .find по таймлайну на кадр.
До 24 сегментов агрегируют последовательные диапазоны сцен по индексам;
частичный прогресс внутри диапазона считается по start/end длительностям.
Тело Video для коротких проектов не меняется. ID, порядок и время не переписываются.
Проверяются 5000 сцен и 100 кадров с синхронным readback, а Node считает обращения
к массиву. Это не проверка/обещание real-time записи 5000 сцен.

Кэш layout — WeakMap только для immutable plan, до 32 cue layouts на план.
Mutable планы пересчитываются. Scratch Canvas перехода — один на target Canvas,
WeakMap позволяет освободить его вместе с target. Изображения заимствуются;
renderer не удаляет оригиналы, не закрывает bitmap и не создаёт AudioContext.
Runtime-память/16 активных картинок и остальные лимиты сессий PR #15 сохранены.

Ошибки: STYLE_UNSUPPORTED (неизвестное оформление), SETTINGS (некорректные либо
смешанные настройки), APPEARANCE (явно неподдерживаемый флаг), TEXT_OVERFLOW,
MISSING_MEDIA, CANVAS, RESOURCES. Существующие EMPTY/OUTPUT/UNSUPPORTED сохраняются.
Нехватка памяти внутри native API всё ещё может завершить вкладку; жёсткая RSS
гарантия не заявляется. Предварительный экспортный обход всех текстов будущему UI
ещё нужно подключить; текущий recorder отбрасывает неуспешную запись при ошибке кадра.

## Независимое доказательство

- `tests/fixtures/editor-canvas/spec.json` — нормативные координаты/цвета/шрифты,
  не считываемые из production. `reference.svg` — отдельная hand-authored SVG
  модель текста и фона, не вызов renderer. Проверяются реальные pixels: маска
  текста (IoU ≥0,80 при max 2 px X/3 px Y различии растеризации), фон и точная
  геометрия draw calls/шрифты/подложки/планета/кольцо/горизонт для 27 сочетаний.
- `review.png` — просмотренный лист фактических Chromium-кадров для ревью, не
  автоматически одобренный oracle. Исправление прозрачного градиента потребовалось
  именно после независимого SVG-сравнения. Reference не перегенерируется из actual.
- Три намеренные порчи реального Canvas (сдвиг текста 30 px, неверный акцент,
  неверный фон) обязаны отвергаться именно независимой пиксельной проверкой.
- Video: прежние 60 RGBA-кадров сравниваются с нулевым допуском. Исторические
  файлы/планы и Safari SHA `ad1ca0a701605af6d80c8de8983ec5ebeb9e8905` не меняются.
  Guard удаляет **одну точную строку** Editor-dispatch, затем прежние resource
  bridges; всё тело Video должно восстановиться побайтно. Сохранены семь атак
  на renderer/encoder/mixer/камеру/фасад/тайминг/CSS, добавлена атака на условие
  dispatch. Исторический checkpoint runtime также сохранён: разрешённые модули
  проверяются differential tests/guard, остальные — исходными SHA-256.
- Реальный тестовый потребитель пишет Editor WebM (3 s, 3 изображения, две WAV),
  проверяет метаданные, seek после loadeddata, цвета, FFmpeg спектр и чёрные кадры.
  Новых пользовательских кнопок нет. Native Safari тестирует HTTP, file://index.html
  и file://автономный HTML; его результаты можно заявить только после реального CI.

## SVG baseline: проверка в WebKit/Safari

В CI `40667739800` воспроизведена ошибка исходной методики, а не изменение
Canvas-профиля. В WebKit исходная маска Canvas начиналась на y=542, SVG — y=525;
в Safari 26.6 — соответственно y=540 и y=523. Ширина строки совпадала
(289,990234375 px), шрифт был загружен, DPR=1, Canvas=720×1280.
`dominant-baseline="middle"` на SVG-группе не задавал ожидаемый baseline дочерним
`text`. Прямое значение `middle` на text устраняло часть сдвига, но SVG middle
и Canvas middle всё равно различались на 4 px в этих средах.

Независимый SVG теперь явно задаёт `dominant-baseline="alphabetic"` **на каждом
text**. Его `dy` — перевод из нормативной Canvas middle-координаты в alphabetic:
разность `actualBoundingBoxAscent` для одного пробного `HgЁ` в двух baseline
на отдельном контексте измерения с независимо заданными font/weight. Равенство
этого перевода по descent проверяется отдельно. Это измерение метрик браузера,
не считывание координат, layout или пикселей production renderer. Все цвета,
геометрия, размеры, шрифты и SVG-фигуры остаются независимой спецификацией.
Нельзя трактовать одинаковые названия baseline как одинаковую геометрию разных API.

Регрессия меняет baseline родительской SVG-группы на hanging и требует неизменной
реальной маски дочернего текста. Все 27 сочетаний по-прежнему должны иметь IoU≥0,80
с прежними пределами 2 px X / 3 px Y; отрицательные сдвиг/цвет/фон остаются
обязательными. Порог, glyph mask, renderer и Video baseline не менялись.

`test-results/editor-canvas/` содержит Canvas, исправленный и исходный SVG,
обе маски, исходную красно-зелёную разницу и JSON метрик. У разницы красный —
Canvas, зелёный — исходный SVG, жёлтый — пересечение. При ошибке снимки сохраняются
как Actions artifacts; компактные маски и метрики также доступны в аннотациях.
Исходный некорректный SVG сохраняется только как диагностический контрпример,
не как проходящий эталон. Новых зависимостей нет.


Safari WebDriver сам по себе не получает macOS sandbox extension для файлов в
рабочем каталоге CI: обнаружен `safari-resource:/ErrorPage.html`, сообщение
`Ignoring request to load this main resource because it is outside the sandbox`.
Native-тест перед file:// навигацией открывает **конкретный тестовый документ**
через стандартный `/usr/bin/open -g -a Safari` (LaunchServices). Изоляция Safari
не отключается. После загрузки проверяется точное location.href; HTTP-подстановка,
пропуск кадров или подмена приложения инъекцией модулей не допускаются.
