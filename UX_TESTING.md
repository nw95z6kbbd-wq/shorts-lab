# Проверка интерфейса перед публикацией

Проверяется ветка PR, опубликованный сайт для этих действий менять не нужно. Версия и история берутся из `js/product.js`; CHANGELOG генерируется из него. Форматы проектов, IndexedDB, миграция и сборка видео в этом изменении прежние.

## Что изменено

Один индикатор находится в закреплённой верхней панели и остаётся видимым при прокрутке. Он читает существующие сообщения редакторов. Пока в любом режиме есть незавершённая запись, «Сохранено» не показывается; ошибка/предупреждение имеют приоритет. При завершённых записях отображается состояние активного режима. Полное сообщение и название режима доступны в подсказке и для экранного диктора. Таймеры автосохранения и транзакции не изменены.

Метаданные готового видео находятся над кнопкой скачивания. После завершения скрываются уже ненужные прогресс и дублирующее сообщение о готовности; повторная сборка остаётся доступной. Если панель выше свободной области окна, она прокручивается вместе со страницей. Внутренней прокрутки для скачивания нет. Изменение масштаба предпросмотра не меняет разрешение видеофайла.

«Что нового» и «О Shorts Studio» доступны в отдельной группе боковой навигации. В компактном боковом меню используются значки с доступными названиями; на телефоне — текстовые кнопки во втором ряду того же меню. Постоянные пункты не дублируются сверху или в версии внизу меню. Однократное предложение открыть историю новой версии сохраняет существующее поведение.

## Ручная проверка в Safari

1. Откройте ветку PR локально. Из каталога приложения запустите:

   ```sh
   python3 -m http.server 8080
   ```

   В обычном профиле Safari откройте `http://localhost:8080`. Для повторного восстановления используйте тот же адрес, порт и профиль. Здесь можно работать с тестовыми данными отдельно от опубликованного origin GitHub Pages.

2. Убедитесь, что в меню видна версия нового выпуска. Откройте «Что нового»: новая запись содержит IndexedDB из PR №5, восстановление файлов/настроек и изменения интерфейса. Предупреждение о локальном хранении сохранено. Закройте окно, перезагрузите страницу: автоматическое предложение не должно появляться повторно для уже просмотренной версии.

3. В текстовом редакторе измените название и сценарий. Индикатор должен перейти в «Сохранение…», затем в «Сохранено». Добавьте несколько сцен и прокрутите к последней. Индикатор остаётся в верхней панели, поля и кнопки не перекрываются. При переходе в видеорежим ещё незавершённая запись редактора не должна превращаться в «Сохранено» только из-за смены режима.

4. В видеорежиме загрузите два изображения, голос и музыку. Измените громкости, переход и длительности сцен. Дождитесь сохранения; проверьте индикатор при прокрутке между идеей, озвучкой, музыкой и последней сценой. Полностью закройте Safari и откройте тот же адрес: файлы и настройки должны восстановиться. Этот ручной перезапуск Safari дополняет автоматические перезапуски Chromium/WebKit.

5. Соберите видео. Метаданные должны находиться непосредственно над кнопкой «Скачать видео» и содержать формат, 720×1280, длительность, размер и состояние аудио. Скачайте и воспроизведите файл; проверьте обе дорожки и изображения. Существующий экспорт MP4 сохраняется. Если Safari на конкретном устройстве возвращает пустой MP4, можно выбрать существующий режим WebM при поддержке браузером; это известное ограничение кодека, а не новое поведение этого PR.

6. Уменьшите высоту окна примерно до 450 пикселей. Откройте оба представления результата: «Анимация» и «Готовый файл». Информация и скачивание должны оставаться одной читаемой группой; до неё можно прокрутить саму страницу, а не содержимое панели. Повторите в адаптивном режиме Safari с шириной 390 и 320 пикселей, затем в альбомной ориентации 667×375.

7. Пройдите навигацию клавишей Tab. Откройте каждый пункт сведений через Enter, переключите вкладки стрелками/Home/End и закройте Escape. Фокус возвращается к кнопке меню. На телефоне проверьте нажатия пальцем; основные пункты редактора и файловые действия остаются доступными.

## Ручное воспроизведение ошибки сохранения

Используйте тестовый проект локальной ветки. Сначала дождитесь «Сохранено». В консоли Web Inspector Safari временно выполните:

```js
window.uxOriginalPut = IDBObjectStore.prototype.put;
IDBObjectStore.prototype.put = function (...args) {
  if (this.name === 'projects') throw new DOMException('UX test', 'QuotaExceededError');
  return window.uxOriginalPut.apply(this, args);
};
```

Измените название проекта. После попытки записи индикатор должен показать «Ошибка сохранения» и остаться видимым после прокрутки. Это не удаляет базу и не записывает повреждённый снимок. Восстановите обычное поведение:

```js
IDBObjectStore.prototype.put = window.uxOriginalPut;
```

Ещё раз измените название и дождитесь «Сохранено». Не закрывайте вкладку с нужными правками в момент искусственного отказа. Обычная перезагрузка также убирает временную подмену API, но ещё не сохранённые правки будут потеряны.

## Автоматические проверки

```sh
node --test tests/*.test.cjs
node scripts/release.cjs check
python3 tests/ux-browser.py
python3 scripts/prepare-site.py
UX_ENTRY=downloads/Shorts-Studio.html python3 tests/ux-browser.py
UX_BROWSER=webkit python3 tests/ux-browser.py
```

UX-тест удерживает настоящую readwrite-транзакцию IndexedDB дольше debounce приложения и проверяет, что индикатор не показывает преждевременный успех, включая смену режима. Затем воспроизводит отказ квоты, проверяет прежнюю сохранённую ревизию и успешное повторное сохранение. Проверки компоновки используют отдельный DOM-образец готового файла: это проверка расположения информации, а не имитация успешного экспорта. Настоящие файлы по-прежнему проверяются существующими `video-browser.py`, `media-browser.py`, `project-browser.py` и заданием настоящего Safari.

Проверяются восемь сочетаний ширины/высоты, длинная страница, отсутствие горизонтальной прокрутки, целиком видимая группа скачивания, клавиатура, возврат фокуса и мобильные касания в WebKit. Обычная и автономная страницы проверяются отдельно. Все прежние проверки сохранения, миграции, восстановления, MP4/WebM и звукового микса сохранены в Actions.

## Сохраняющиеся ограничения

Локальная база зависит от origin, браузера, профиля, квоты и его политики удаления данных. Перед закрытием дождитесь сохранения. Облако и полная резервная копия проекта здесь не добавлены. WebKit в адаптивном режиме не заменяет проверку физического iPhone. Подробности хранения — в `PROJECT_STORAGE.md`.
