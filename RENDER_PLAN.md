# Общий расчётный RenderPlan

Инфраструктурный этап после Studio DTO 2. Нового UI ручной видеосборки нет.
Версия продукта остаётся **1.4.0 Unreleased**; история выпусков не изменена.
База IndexedDB 2, DTO и ZIP 1 остаются прежними.

## Модули и границы

- `js/render-plan.js` — один расчёт сцен, границ, cues, выбора кадра и SRT.
- `js/render-adapters.js` — `fromVideo(draft)` и `fromEditor(project)`.
- `js/video-core.js` сохраняет прежние `makePlan`, `frameAt`, `chunks`,
  `generateSrt` как совместимый фасад общего модуля. Генерация шаблонов,
  нормализация видеочерновика, геометрия камеры, форматы и WebM остаются здесь.
- `video-ui.js` строит общий план через Video adapter. Один объект плана и
  один набор runtime-ресурсов используют Canvas-предпросмотр и recorder.
- Renderer получил отдельный необязательный аргумент `resources`; recorder
  передаёт его дальше. Алгоритм рисования и MediaRecorder не переписаны.
  `video-audio.js` не изменён.

План — временный результат вычисления. Он не входит в DTO, IndexedDB или ZIP,
не вызывает сохранение, не открывает базу и не загружает файлы. Никаких
Canvas/Image/AudioBuffer/Blob/Map/временных URL в результате адаптеров нет.
Декодированные изображения находятся в отдельном `resources.images: Map`;
аудиобуферы передаются прежними аргументами recorder/mixer.

## Контракт версии 1

```js
{
  kind: 'shorts-render-plan', version: 1,
  source: { mode: 'editor' /* либо video */, dtoVersion: 2, projectId: '...' },
  output: { width: 720, height: 1280, fps: 24 },
  title: '...', durationMs: 2400,
  timeline: [{ id, text, index, startMs, endMs, cues,
               visual, imageId, camera, transition }],
  cues: [{ startMs, endMs, text, words }],
  omittedScenes: [{ id, reason }],
  timing: { policy: 'editor-reading', wordsPerMinute: 150 },
  subtitles: { policy: 'editor-scene', enabled: true,
               highlight: 'none', alignment: 'scene-boundaries' },
  appearance: { requested, resolved, supported, limitations },
  audio: { policy, voice, music, shortSource, durationFromAudio: false },
  media: [{ assetId, kind }],
  exportSettings: { format: 'auto', profile: 'shorts-720p' },
  theme: null, caption: null // совместимые поля; для неподдерживаемого editor — null
}
```

`projectId` есть у редактора; видеочерновик не получает выдуманный ID.
Порядок и ID существующих сцен сохраняются. Расчёт не генерирует UUID и не
читает часы. Некорректные/дублированные ID адаптеры отклоняют. Для старого
editor DTO 1 выполняется чистое преобразование в памяти с помощью Core:
исходный проект не меняется и не записывается. Результат адаптера определяется
входными данными, независимо от активной вкладки и состояния второго режима.

`startMs`, `endMs`, `durationMs` — целые миллисекунды. Общая длительность
редактора должна помещаться в safe integer. Продолжительность сцены равна
`endMs - startMs`. Проектные данные сохраняют все сцены; нулевые расчётные
сцены редактора перечисляются в `omittedScenes`, без изменения DTO.
Пустой editor-план допустим как результат расчёта (0, пустые массивы), но
`frameAt`/renderer/recorder явно отказывают для него.

## Политики времени

| Политика | Расчёт |
| --- | --- |
| `video-auto` | Прежняя общая длительность и веса `max(4, число слов)`; прежнее округление границ, пустые animated-сцены пропускаются |
| `video-manual` | Прежняя сумма округлённых `durationSeconds * 1000`; сохраняются намеренные сцены без текста |
| `editor-reading` | Только отредактированные `scenes[].text`, `Core.durationMs()` при 150 слов/мин; сохранённые overrides не применяются в этом режиме |
| `editor-manual-or-reading` | Положительный `scenes[].durationMs`; при null — оценка по словам |

Видео сохраняет ограничения: до 12 сцен, текст DTO до 280 символов,
ручная сцена 0.5–60 секунд, итог 0.5–60 секунд. Для публичного старого
`VideoCore.makePlan()` остаётся прежняя форма результата и прежние допуски
расчётного API; он не превращён в дополнительный DTO-нормализатор.

Редактор не получает видеолимиты: до 5000 сцен и прежние лимиты Core на текст,
ручная длительность может быть 1 ms или больше 60 секунд. Пустая сцена с
явной положительной длительностью остаётся в плане; в reading-режиме
нулевая оценка не заменяется выдуманным минимальным временем изображения.
`script` и `sourceScript` не используются для регенерации отредактированных
сцен и не подменяют их текст.

## Субтитры и аудио

- `editor-scene`: один cue на непустую по словам сцену, SRT по её границам.
  При reading-тайминге SRT совпадает с прежним `Core.generateSrt()`.
- `video-chunks-6`: прежние группы до 6 слов, пропорциональные интервалы
  внутри сцены и оценочная подсветка текущего слова.
- `editor-chunks-6`: только явная настройка `subtitles.mode: 'chunks'` DTO 2;
  интервалы пропорциональны словам, подсветка остаётся `none`.
- `enabled: false` даёт пустой список cues. Политики не выбираются по длине
  текста и не меняются молча. Текущие кнопки ручного редактора не подключены
  к новому плану и сохраняют прежнее поведение.

Распознавания речи, TTS и выравнивания с голосом нет. Оба источника стартуют
в 0; длинный источник обрезается концом плана, короткий не повторяется,
после его окончания остаётся тишина. Музыка не зацикливается. Длительность
ролика не растягивается до длины голоса или музыки. Существующий технический
источник тишины в микшере не является зацикливанием музыкальной дорожки.

`audio.voice/music` содержат постоянные ID/имена оригиналов и громкости;
у музыки — `fadeInSeconds`/`fadeOutSeconds`. Единицы названы явно и совпадают
с API текущего микшера: дробные legacy fade-секунды не округляются заново.
Editor DTO 2 преобразует целые fade-миллисекунды делением на 1000.
`RenderPlan.audioOptions()` — один источник параметров preview/record.
Аудиобуферы и их фактическая длина в расчёт не поступают.

## Точное оформление, без приблизительных замен

| Запрошенное оформление | Текущий Canvas |
| --- | --- |
| Video: mystery / space / sunrise / neon | Поддерживается без замены |
| Video: accent / classic / outline и auto-fit | Поддерживается прежними правилами |
| Editor: cosmos / dusk / minimal | Не поддерживается точно; theme = null |
| Editor: accent / classic / outline | CSS-варианты не равны видео: не объявляются поддержанными |
| Editor: small / medium / large и CSS-компоновка | Не поддерживаются точно; размер/компоновка = null |
| Изображения, прежние камера/переходы | Ссылки и параметры сохранены в обоих адаптерах |

В `appearance.requested` сохраняются namespace и точные исходные настройки.
`resolved` показывает доступное renderer-оформление; `supported/limitations`
явно указывают пробелы. **cosmos не превращается в space**, dusk — в mystery.
Названия одинаковых caption-стилей также не доказывают совпадение CSS/Canvas:
у ручного preview, например, иначе устроены выделение слов, шрифты и размер.

`assertRenderable()` отказывает для неподдерживаемого общего плана до
рисования/записи. Поэтому ручные темы пока нельзя экспортировать через
этот renderer без будущей точной реализации либо отдельно согласованного,
явно выбранного оформления. Совместимый фасад видео нельзя применить
к editor-плану для обхода этой границы. Ручной DOM-предпросмотр не изменён.

## Доказательство совместимости

Эталоны до изменений: `tests/fixtures/render-plan/`, main
`ad1ca0a701605af6d80c8de8983ec5ebeb9e8905` (после Merge PR 11).
Сохранены независимые старые VideoCore/renderer, полные планы/SRT и значения
кадра на границах. Эталоны не следует перегенерировать новым кодом.

Node сравнивает прежний фасад с эталонами и независимо со старой реализацией
на 200 детерминированных наборах. Тестируются оба адаптера, ручные/reading
длительности, длинные/пустые тексты, порядок/ID, политики субтитров, медиа,
фракционные fades и явные ограничения оформления.

Chromium/WebKit/native Safari сравнивают **все RGBA-пиксели 60 кадров** старого
и нового renderer, включая публичный legacy API, PNG/JPG/WebP, камеры и
переходы. Проверка ZIP-восстановления инструментирует настоящее preview и
запись: проверяет один объект плана/ресурсов и соответствие микшера плану,
после чего выполняется прежний реальный экспорт с анализом файлов.
Автономный HTML проверяется с запретом всех дополнительных сетевых запросов.

```sh
node --test tests/*.test.cjs
python scripts/prepare-site.py
CHROMIUM_PATH=/usr/bin/chromium python tests/render-plan-browser.py
RENDER_ENTRY=downloads/Shorts-Studio.html python tests/render-plan-browser.py
RENDER_BROWSER=webkit python tests/render-plan-browser.py
sudo /usr/bin/safaridriver --enable # только macOS
python tests/safari-product.py
```

## Что остаётся перед подключением ручной видеосборки

Нужны точное согласованное оформление, runtime-загрузка/проверка медиа
редактора, UI управления и обратимая интеграция контроллера. Адаптер не
доказывает наличие или декодируемость исходников по одному ID. Существующая
граница ZIP 1 для DTO 2 остаётся: прежде чем включать пользовательский
медиа-UI, необходим отдельный переносимый формат с обратным чтением старых
архивов. Этот этап не меняет ZIP, IndexedDB, сохранённые проекты и миграции.
Поддержка видеоклипов также не добавлена; её будущему адаптеру потребуются
свои явно заданные trim/source-time правила, а не второй видеодвижок.
