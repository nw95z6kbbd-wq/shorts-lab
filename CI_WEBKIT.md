# Устойчивое окружение WebKit в GitHub Actions

## Диагноз

Workflow `Check and deploy GitHub Pages`, запуск [40388307378](https://github.com/nw95z6kbbd-wq/shorts-lab/actions/runs/40388307378), коммит main `91944ede05d4f4e146eb5b8b8cecef6ebabca6e0`:

- Попытка 1: установка зависимостей WebKit 27 октября 2026 с 00:37:07 до 00:42:12 (Asia/Yekaterinburg) — 5 минут 5 секунд, exit 124.
- Попытка 2: 27 октября 2026 с 00:45:05 до 00:50:10 (Asia/Yekaterinburg) — те же 5 минут 5 секунд, exit 124.
- В шаге стояло `timeout 5m python -m playwright install-deps webkit`. Код 124 выдаёт GNU timeout; тесты WebKit ещё не запускались. Время apt включает обновление индексов, разрешение зависимостей, скачивание и установку. Сетевые тайм-ауты apt по 30 секунд и retry 1 не ограничивают всю последовательность загрузок пятью минутами.
- По предоставленным владельцем логам apt должен загрузить 117 MB и не успевает до внешнего дедлайна. Аннотации и времена обеих попыток подтверждены через GitHub API. Полный архив логов из рабочей среды недоступен из-за запрета доступа к CDN; без него нельзя достоверно назвать конкретный медленный mirror/пакет.
- Chromium и настоящий Safari успешны; Pages корректно пропущен, поскольку обязательный WebKit не прошёл.

## Решение

Только job `webkit` выполняется в официальном образе Microsoft `mcr.microsoft.com/playwright/python:v1.62.0-noble`, закреплённом по проверенному manifest digest. Python, браузеры и системные библиотеки установлены при сборке образа. В job больше нет `apt`, `install-deps` и загрузки браузеров через `playwright install`. Python-пакет Playwright устанавливается из прежнего `requirements-dev.txt`: upstream удаляет пакет, которым собирались браузеры, из конечного образа.

Preflight сверяет версию установленного пакета с тегом образа, проверяет наличие ожидаемого бинарника и действительно запускает WebKit. Несовпадение версий, отсутствующая библиотека или ошибка запуска приводят к ошибке job, а не зелёному пропуску. Общий job ограничен 20 минутами, включая холодную загрузку образа и все прежние тесты; это запас для registry, а не снятие ограничений с тестирования. `--init` помогает завершать дочерние процессы; `--shm-size=1g` предоставляет ограниченный объём shared memory браузеру.

Почему не кэш apt: кэш архивов не восстанавливает установленные пакеты, не устраняет обновление индексов и разрешение зависимостей, а набор версий зависит от состояния Ubuntu-репозиториев. Кэшировать `/usr` или dpkg-базу поверх свежего runner небезопасно. Простое увеличение прежних пяти минут оставляет тот же сетевой источник отказов.

Компромисс: amd64-образ содержит все браузеры и имеет около 950 MiB сжатых слоёв, больше прежних 117 MB apt. Загрузка слоёв идёт из MCR с обычными механизмами Docker; установленное окружение воспроизводимо и не зависит от состояния Ubuntu mirrors при каждом тесте. Наличие тёплого кэша на новом hosted runner не гарантируется. Сбой MCR или PyPI по-прежнему может остановить job; ошибки не скрываются.

## Сохранённые проверки и публикация

Все прежние команды WebKit сохранены: исходный и автономный интерфейс, мобильная эмуляция, UX/toast/sticky, изолированная IndexedDB, миграция, восстановление проектов и существующие проверки экспорта при поддержке кодека. Chromium/FFmpeg и настоящий Safari на macOS не изменены. Ограничения кодеков WebKit не отменяют реальные проверки файлов в Chromium и Safari.

Deploy по-прежнему зависит от `[check, webkit, safari]`. Только при успешных обязательных jobs, ref `refs/heads/main` и событии вне pull_request загружается артефакт `_site` и запускается `actions/deploy-pages`. PR ничего не публикует. После ручного объединения новый push в main автоматически выполнит этот workflow; повторный запуск только старого упавшего шага использует старое определение workflow и не проверяет исправление.

Версия продукта остаётся прежней; файлы приложения, форматы пользовательских данных и `requirements-dev.txt` не меняются.

## Обновление окружения

При изменении Playwright одновременно обновляйте пакет в `requirements-dev.txt`, официальный тег и его проверенный digest в `pages.yml`. Digest можно получить через MCR v2 manifest API с Accept для manifest list / OCI index; default schema-v1 digest не следует подставлять вместо современного manifest list. Preflight намеренно требует совпадения версий.

В рабочей среде доступна проверка manifest/tag и upstream Dockerfile, но скачивание слоёв Docker было отклонено (`Forbidden`). Локальный запуск этого образа здесь не подтверждён; фактическая загрузка и все тесты проверяются отдельным прогоном PR в GitHub Actions. Это внешнее ограничение среды, не ошибка WebKit.
