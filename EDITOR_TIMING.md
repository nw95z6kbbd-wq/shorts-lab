# Тайминги ручной «Студии»

Внутреннее обновление 1.4.0 Unreleased. Пользовательской сборки видео в ручной
«Студии» этот этап не добавляет. Video, MediaRecorder, микшер, DB v2, DTO и ZIP
v1/v2 не изменены.

## Что было несогласованно

До интеграции `app.js` вызывал `ShortsCore.durationMs()`, `timeline()`,
`totalDuration()` и `generateSrt()` независимо от Editor adapter. Ручные
`durationMs`, режим `timing`, отключение субтитров и `subtitles.mode` DTO 2 не
участвовали в отображении таймингов и SRT. После открытия такого проекта через
JSON/IndexedDB/ZIP эскиз, подписи и SRT могли расходиться с RenderPlan.

## Единственный расчёт

`js/editor-timing.js` — тонкий UI-адаптер. `compile(project)` один раз вызывает
`ShortsRenderAdapters.fromEditor(project)` и возвращает `{plan, byId}`. `byId`
привязывает строки UI к постоянным ID; время берётся из `plan.timeline`.
Пропущенная планом нулевая сцена отображается с одинаковыми start/end на текущей
границе, не добавляя длительности. Новый тайминговый движок не вводится.

`app.js` держит один вычисленный план для текущих правок: карточки сцен,
точное итоговое время, старый текстовый DOM-эскиз и воспроизведение, список cue
и обе кнопки SRT используют его. SRT создаётся непосредственно
`ShortsRenderPlan.generateSrt(plan)`. Оценка под исходным сценарием отдельно
подписана как оценка исходного текста и не определяет время отредактированных
сцен. Отображение времени теперь сохраняет миллисекунды, а не округляет итог
вверх до целой секунды. RenderPlan не записывается в проект или ZIP.

### Длительности

- «Авто» (`reading`) использует существующие 150 слов/мин, `Math.round` из Core
  и актуальный текст каждой сцены. Определение слова (включая Unicode) не меняется.
- «Вручную» (`manual`) использует `durationMs`; пустое поле задаёт `null`, то есть
  fallback к расчёту по тексту. Переключение в Авто не стирает overrides.
- UI принимает секунды с точкой/запятой и до трёх десятичных знаков, включая
  `.5`/`,5`. Разбор через BigInt исключает потерю точности и тихое округление.
- Пределы берутся из DTO 2: от 1 до `Number.MAX_SAFE_INTEGER` целых миллисекунд
  для override. Ручной ноль, отрицательные, NaN/Infinity, экспоненциальная запись,
  четвертая десятичная цифра и переполнение отклоняются. Ноль автоматического
  расчёта допустим и не превращается в минимальную длительность Video.
- Суммарное переполнение отклоняет сам RenderPlan. Столь большой допустимый DTO
  не является обещанием успешной записи видео такой длительности.
- Чтение/перестановка/обычное редактирование DTO 1 сохраняют его версию. Только
  явный выбор новой настройки (Manual, другая политика субтитров или их
  отключение) вызывает существующий `upgradeProject()`. Действие «Авто» поверх
  старого Авто не конвертирует проект.

До интеграции обнаружен крайний дефект: при допустимой ручной длительности
9007199254740990 мс и трёх словах float-умножение возвращало конец cue на 1 мс
раньше конца сцены (frozen `unsafe-cues-before.json`). Editor теперь вычисляет
доли с точным целочисленным округлением; формула Video остаётся прежней.

### Субтитры и ошибки

`scene` означает `editor-scene`, `chunks` — `editor-chunks-6`. Отключение
субтитров даёт пустой SRT; кнопки скачивания отключены. Пустые/нулевые сцены
сохраняются в проекте, но ведут себя по действующей политике Editor adapter.
Положительная пустая ручная сцена имеет время, но не реплику.

Слишком короткая длительность для групп не переключает политику автоматически.
Ошибка SUBTITLES остаётся видимой, пока пользователь явно не увеличит время,
изменит текст, выберет реплики по сценам или выключит субтитры. Сценарий
«1 мс, семь слов, chunks» обязательно проверяется в браузере.

При некорректной правке поля сохраняются во вкладке для исправления: сырой
невалидный ввод не включается в DTO; валидная длительность с ошибкой chunks
остаётся в черновике. План и временные подписи сбрасываются, SRT/проигрывание/
JSON отключаются; ZIP snapshot выдаёт ошибку. Автосохранение не отправляет
такой черновик в очередь хранилища. Предыдущие корректные записи и оригиналы
не меняются. Исправление снова разрешает сохранение полного корректного DTO.
Кнопка отмены возвращает последнее корректное состояние во вкладке (оно может
быть новее последнего commit IndexedDB). Если уже загружен некорректный проект,
без корректного состояния для отмены, требуется явное исправление политики.
Закрытие вкладки с ошибкой теряет несохранённый черновик; предупреждение
остаётся видимым. Это не новая гарантия сохранения невалидных данных.

### Порядок и масштаб

«Выше»/«Ниже» меняют порядок существующих объектов сцен; ID, текст, durationMs,
включая неактивные изображения, камера и переходы сохраняются. Выбор привязан
к ID. Основной/исходный сценарий не пересоздаётся. Новые ID создаются только
при явном добавлении/повторном разбиении. Лимит 5000 сцен сохраняется.

Карточки согласуются по ключу ID при структурных действиях; ввод текста и
длительности не перестраивает список, не теряет фокус/сырой ввод. При пересчёте
обновляются только изменившиеся подписи/атрибуты. Список cue строится лениво,
когда открыта вкладка субтитров. Выбор текущего кадра использует бинарный поиск
RenderPlan; индикатор DOM-эскиза ограничен 24 сегментами.
Сам расчёт и обновление строк остаются O(n), первая загрузка 5000 карточек
также O(n). Виртуализация не добавлена; её стоит измерить отдельно на старых
телефонах. Тест замеряет ввод в проекте 5000 сцен и проверяет неизменность
узлов, ID и фокуса; это не обещание поддержки записи 5000 сцен.

## Совместимость и границы

Некоторые валидные старые DTO 1 допускают ID с пробелами или большей длиной,
чем разрешает DTO 2. Adapter теперь берёт только значения по умолчанию из
временного DTO 2 и сохраняет исходную идентичность DTO 1. Чтение, Reading и
перестановка таких проектов работают без переименования и автозаписи DTO 2.
Явное включение DTO-2-настроек для несовместимых ID отклоняется с ошибкой.
Безопасная миграция идентичности требует отдельного решения; здесь ID не
подменяются молча. Неизвестные версии и значимые настройки отвергаются.

Форматы проектов, оригиналы, очистка, recovery, CAS и транзакции не меняются.
Граница `saveNow`/`backupSnapshot` лишь запрещает передачу невалидного черновика;
очередь хранилища сохраняет прежние гарантии. Исходные функции Core остаются
доступными для других клиентов, но app не использует их для scene/SRT timing.

## Проверки и ручная приёмка

Перед изменениями зафиксированы SHA основного main, исходные app/index,
видеопланы, 60 кадров RGBA, восемь отрицательных проверок guard и фиксированный
исторический Safari SHA. `tests/editor-timing.test.cjs` защищает неизменность
Video/storage/Core и узкую добавку к сохранению. Старый guard не изменён.

`tests/editor-timing-browser.py` использует реальные формы и скачанный SRT,
ZIP 1/2, PNG/JPG/WebP/voice/music, перенос в чистый контекст и полный перезапуск
процесса. Мобильная автономная сборка запускается без сетевых зависимостей.
`tests/editor_timing_native.py` включён в прежний Native Safari job через
`studio_data_native.py`, не изменяя Safari baseline/renderer/recorder.

Перед Merge в настоящем Safari на macOS:

1. Открыть существующий проект DTO 1 и ZIP 1: Reading и SRT совпадают;
   редактирование/перестановка не конвертируют формат.
2. Включить Manual, ввести 1,234 сек и оставить другое поле пустым. Проверить
   подписи границ/итог, Reading → Manual и сохранность значений.
3. Переставить три сцены. Выбранная сцена, её текст/параметры и SRT остаются
   связанными с тем же ID. Добавить/удалить сцену, отменить удаление.
4. Выбрать группы по 6 слов; для семи слов задать 0,001 сек. Убедиться в явной
   ошибке и недоступности экспорта. Перезагрузка в отдельной вкладке должна
   открыть прежнюю корректную сохранённую версию. Вернуться и явно исправить
   длительность/политику, затем проверить SRT.
5. Проверить 0, отрицательное/нечисловое число, 4 десятичных знака, кнопку отмены;
   сырой ввод/фокус не должны пропадать при ошибке. Выключить/включить субтитры.
6. С проектом DTO 2 и оригиналами скачать ZIP 2, восстановить в чистом браузере,
   закрыть Safari полностью и открыть снова. Проверить порядок/длительности,
   доступность изображений/аудио и независимость «Видео по идее».
7. На узком окне/телефоне проверить поля и «Выше/Ниже» с клавиатуры, отсутствие
   горизонтальной прокрутки, toast и sticky. Проверить обычный Video MP4/WebM.
8. Открыть автономный HTML из `file://`: startup/Reading/Manual/SRT. Ограничения
   локального IndexedDB зависят от Safari; ZIP остаётся независимой копией.

Ни успешный Chromium, ни проверка Native-helper в Chromium не заменяют
результат Native Safari CI. Если GitHub API не даёт открыть PR, проверки Safari
и WebKit остаются обязательными после его ручного создания.

## Исправление двух ложных CI-падений PR #17

Диагностический запуск [40729211034](https://github.com/nw95z6kbbd-wq/shorts-lab/actions/runs/40729211034)
на `0f373ae` установил причины на реальных WebKit и Safari. Обезличенные
наблюдения сохранены в `tests/fixtures/editor-timing/ci-failure-diagnostics.json`.

1. В строке 55 Python было несколько assert. WebKit падал **до вызова очистки**:
   ожидалась строка `2,345`, но активное поле хранило введённое `2.345`.
   `select_option()` отправляет input/change, не переводя фокус. В WebKit
   фокус оставался в поле даже при Reading → Manual; событий blur не было.
   DTO сохранял правильные 2345 мс. Это соблюдает правило не переписывать
   активное поле, а не ошибка decimal parsing или fallback. Тест теперь явно
   переводит фокус перед проверкой форматирования, затем отдельно проверяет
   пустую строку, текущий `durationMs: null`, commit IndexedDB и read-only reload.
   Никакие ожидания не заменены и задержки для этого исправления не добавлены.
2. Native Safari передавал `before_error` из JavaScript через safaridriver в
   Python и назад. Порядок ключей в 15 JSON-объектах изменялся; все значения
   DTO (включая timestamps, scene ID и durationMs), порядок массивов и SHA-256
   оригиналов оставались теми же: `changeCount: 0`. Старое JSON.stringify
   сравнение ошибочно воспринимало изменение порядка членов объекта как
   повреждение данных. Это не поздний autosave и не изменение изображений/аудио.

`editorTimingDiff()` теперь сравнивает все собственные поля, типы, массивы,
значения и хеши структурно, без зависимости от порядка ключей объекта. Никакие
поля, timestamp или media hash не исключаются. Диагностика показывает путь,
числовое значение либо длину/хеш строки; названия исходников и тексты проекта
не выводятся. Длинный отчёт ограничен числом строк, но общее число расхождений
считается полностью и любое расхождение продолжает приводить к ошибке.

Два новых Node-теста воспроизводят permutation при W3C round-trip, проверяют
сам invalid-draft assert и доказывают отказ при реальном изменении timestamp,
длительности, порядка сцен, текста/ID или хеша оригинала. Браузерный тест
намеренно переставляет ключи эталонного снимка перед проверкой невалидного
ввода. Сообщение пустого AssertionError теперь включает файл/строку/функцию
в `check-errors.py`, сохраняя прежний ненулевой exit code.

Рабочие app.js, parser длительности, IndexedDB, DTO, ZIP и генератор видео для
этих исправлений не менялись. Сохранены прежняя задержка автосохранения и его
защита от невалидного черновика. Native Safari печатает отдельное подтверждение
равенства полей/хешей после фактического выполнения новой проверки; результат
Chromium shim не считается подтверждением Safari.
