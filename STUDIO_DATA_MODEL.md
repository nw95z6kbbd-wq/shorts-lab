# Подготовка модели ручной Студии: технический этап

Это инфраструктура, а не ручной видеоредактор. UI заполнения новых полей,
сборка видео в Студии, общая временная шкала и адаптер рендера пока не добавлены.
Продукт остаётся **1.4.0 Unreleased**; отдельный пользовательский релиз для этого
этапа не назначен. Рекомендуется включить его в следующую функциональную версию
после проверки данных, без отдельной публикации инфраструктуры.

## Три независимых номера формата

- `editor.state.version`: старый DTO **1**, подготовленный DTO **2**.
- Физическая версия IndexedDB `shorts-studio.projects`: **2**. Это барьер для старых писателей.
- Конверт записи `projects.schemaVersion`: по-прежнему **1**; ZIP: по-прежнему **1**.

`createProject()` и обычный редактор продолжают создавать DTO 1.
`parseProject()` читает 1 без преобразования в 2; запись при чтении не выполняется.
`upgradeProject()` — явное чистое преобразование в памяти, без обращения к базе.
Оно сохраняет ID проекта/сцен, текст, sourceScript, оформление и updatedAt.
Простое открытие существующей базы обновляет только физическую версию, не DTO,
ревизии, оригиналы, предыдущие состояния или метаданные миграции.

## DTO 2

Все данные — JSON. Базовые поля DTO 1 остаются на прежних местах:
`version`, `id`, `name`, `script`, `sourceScript`, `scenes`, `selectedSceneId`,
`style`, `updatedAt`. Ограничения ручного текста прежние: 1 000 000 символов,
5 000 сцен; ограничения видеорежима 280/12 сюда не переносятся.

| Поле | Контракт |
| --- | --- |
| `scenes[].id`, `text` | Постоянный уникальный ID, редактируемый текст; дубликаты ID в DTO 2 — ошибка |
| `scenes[].durationMs` | `null` (оценка по словам) или положительный safe integer миллисекунд |
| `scenes[].visual` | `animated` / `image` |
| `scenes[].imageId`, `imageName` | ID оригинала в assets или null; имя до 200 символов |
| `scenes[].camera` | `zoom-in`, `zoom-out`, `pan-left`, `pan-right`, `static` |
| `scenes[].transition` | `crossfade`, `slide`, `zoom`, `none` |
| `timing` | `reading` / `manual` — намерение для будущего адаптера |
| `audio.voice` | `{assetId, name, volume}`; volume 0–1, по умолчанию 0.7 |
| `audio.music` | Те же поля плюс `fadeInMs`, `fadeOutMs`: неотрицательные целые ms; defaults 0.25 / 1000 / 1000 |
| `subtitles` | `{enabled: true, mode: 'scene'}`; mode также `chunks` |
| `style` | Прежние caption/size/theme ручной Студии; новые значения пока не поддерживаются |
| `exportSettings` | `{format: 'auto', profile: 'shorts-720p'}`; format также `webm`; профиль резервирует существующие 720×1280, 24 fps |

Новые поля заполняются дефолтами в возвращаемом DTO 2, например для добавленной
через существующий редактор сцены. Исходный объект не меняется. Назначение полей
пока только хранение: существующие предпросмотр/SRT ручной Студии продолжают
рассчитывать время по словам. Будущий адаптер должен отдельно проверять общую
длительность, возможности кодека, отсутствие исходников и пригодность медиа.

Разрешённые поля перечислены явно. Неизвестная версия, новое поле или значение
настройки DTO 2 даёт `UNSUPPORTED`, а не молчаливое удаление. Нельзя передавать
Canvas, ImageBitmap, AudioBuffer, URL `blob:`/`data:`/сетевые URL вместо ID.
Временные декодированные объекты не входят в DTO. Некорректные значения не
обрезаются и не зажимаются до допустимого диапазона. ID медиа — до 200 символов.

## Поиск ссылок, сохранение и очистка

`ShortsProjectDB.assetUses(slot, state)` нормализует DTO и возвращает Map ID →
назначение; `references()` получает уникальные ID из этого же механизма. Для
DTO 1 editor список пуст; DTO 2 учитывает изображения всех сцен (даже если выбран
animated) и обе audio-ссылки. Video DTO 1 учитывает прежние imageId/voiceAssetId/
musicAssetId. Один оригинал можно использовать многократно и в обоих режимах.

GC вызывается только в транзакции обычного сохранения после проверки всех
текущих и предыдущих снимков обоих слотов. Ошибка чтения ссылок, неподдерживаемый
DTO или конверт отменяют всю транзакцию. Неизвестную будущую голову нельзя
заменить более старым readable previous: load отключает запись, save/restore
отказываются. Неизвестный previous также блокирует запись/очистку.

Очереди, epochs UI, CAS ревизий и атомарная запись состояния + новых исходников
сохранены. Оригиналы стали неизменяемыми по ID: повтор с теми же байтами,
MIME, именем и kind допустим, иной файл с тем же ID отменяет транзакцию.
Для замены исходника нужен новый ID; роли voice/music могут ссылаться на один
аудиооригинал. Квота, исключение и abort сохраняют прежние головы/медиа.

Исторические missingAssets и legacy recovery не удаляются. Если исходника нет,
нельзя восстановить его из имени: запись известного исторического пробела
сохраняется, но новый висячий ID отклоняется. Этот этап не исправляет ранее
утраченные оригиналы.

## Старые вкладки и обновление IndexedDB

Реальный клиент 1.4.0 вызывает `indexedDB.open(name, 1)` и закрывает соединение
в versionchange. Открытие новой версии 2 ждёт завершения старых транзакций;
новые материалы DTO 2 пишутся только после успешного обновления. После него
старый open(1) завершается VersionError до любой очистки/записи.

Если вкладка не закрыла соединение, получаем BLOCKED: сохранение не включается,
нужно закрыть старые вкладки и повторно открыть страницу. Open нельзя отменить,
поэтому поздний upgradeneeded после BLOCKED/тайм-аута явно abort-ится. Не будет
скрытого обновления базы после сообщения об ошибке. Все createObjectStore
защищены проверкой существования; дополнительные stores остаются нетронутыми.
Повторное открытие не повторяет преобразование данных. VersionError новой
программы при ещё более новой базе также не включает fallback-запись.

**Откат:** после использования базы 2 сайт с клиентом 1.4.0/физической версией 1
больше не сможет сохранять на этом origin. Безопасный откат обязан сохранить
новый storage/DTO-reader и номер базы 2; нельзя понижать или удалять базу.
Пользователь получает сообщение о необходимости обновления. Физический барьер
не защищает от произвольного стороннего скрипта/DevTools на том же origin,
но защищает именно существующий выпущенный клиент с фиксированным open(1).

## Граница ZIP

ZIP 1 не умеет переносить новые поля/материалы ручной Студии. Поэтому **любой
editor DTO 2**, даже без исходников, явно отклоняется форматом и captureBackup
до предложения скачивания. Импорт ZIP 1 с DTO 2 также отклоняется. Исходные
данные остаются нетронутыми; неполный архив не предлагается как успешная копия.
Все прежние ZIP 1 с editor DTO 1 продолжают читаться/писаться без изменения
контракта. Будущая поддержка DTO 2 требует нового ZIP-формата с обратным чтением
ZIP 1, единым assetUses и remap ссылок обоих слотов. Этот PR её не реализует.
Обычный JSON редактора не является переносимым архивом оригиналов.

## Эталонные и автоматические проверки

`tests/fixtures/studio-safety/` зафиксирован **до изменений** из main
`a47eb7554f9ee22099cd9c5a9facdf1622369c7d`: DTO обоих режимов, ZIP с настоящим PNG,
старые core.js и project-db.js. Замороженный клиент используется только тестами,
не попадает в сайт. Эталоны не следует перегенерировать новым writer.

```sh
node --test tests/*.test.cjs
CHROMIUM_PATH=/usr/bin/chromium python tests/studio-data-browser.py
CHROMIUM_PATH=/usr/bin/chromium python tests/studio-ui-browser.py
python scripts/prepare-site.py
STUDIO_ENTRY=downloads/Shorts-Studio.html python tests/studio-ui-browser.py
PERSISTENCE_BROWSER=webkit python tests/studio-data-browser.py
PERSISTENCE_BROWSER=webkit python tests/studio-ui-browser.py
```

Изолированные базы проверяют реальные записи/байты, старые соединения,
BLOCKED/late-upgrade, VersionError, незавершённую транзакцию, частичную старую
схему, CAS, quota/abort, предыдущие снимки и future head/previous. Две вкладки
Chromium/WebKit запускают именно старый замороженный клиент. UI-тест проверяет
редактирование DTO 2, независимость режимов и SHA-256 PNG/JPG/WebP/двух WAV после
полного перезапуска процесса браузера, в исходной и автономной сборке.
Native Safari запускает те же изолированные DB/adapter assertions. Прежние
проверки видео, ZIP, мобильной навигации и автономного HTML остаются обязательными.
